Eight screens, framed for four user personas: the tester who wants defaults, the vibe-haver who wants something funny without thinking, the lore-rich user with paragraphs of backstory, and the reference-image user who has visual inspiration in mind. One flow that absorbs all four through inspiration archetypes, progressive disclosure, and a cheap prototype gate that derisks the rest of the run.

Changes since v0.1
  • New Step 1: Inspiration. Archetype gallery + reference image upload + "start blank" — absorbs three of four custom personas at the entry point.
  • New Step 4: Prototype. Generate one base sprite, history strip, always-visible feedback field, "see revised prompt" expander. Fail cheap before burning 7 more imagegens.
  • Brief expanded (Step 2). Larger description field, optional "Go deeper" disclosure for backstory / speech style / quirks / visual notes.
  • Example pet swapped from cozy Mochi to grumpy Wendell to demonstrate the archetype-driven path.

01

Inspiration gallery

New step that absorbs three custom personas at one entry point. Vibe-havers pick an archetype, reference-image users drop a file, lore-rich users skip both with "start blank."

  • Six hand-curated archetypes — pre-rendered concept thumbnails (no imagegen burned on browse traffic), one-line vibe descriptors, and chip-tag presets that flow into Step 2.
  • "and / or" divider, not "or". You can pick an archetype and upload a reference. They compose; they don't compete.
  • Reference-image card shown here in the "uploaded" state. Empty state would show a dashed dropzone with "drop an image or click to browse."
  • "Start completely blank" is a small text link, not a button. Honest hierarchy: most users want a starting point, the blank path is for power users who already know what they want.
  • Picking an archetype pre-fills the description, personality chips, and palette in Step 2. User edits from there.
The "I don't know what I want" problem solved without chat. Archetypes are draft starting points users can react to and edit, not prescriptions. They give indecisive users something to push against without dragging a chat surface into the flow.

02

Brief, but flexible.

Same form shape as v0.1 but with three real changes: pre-fill from archetype, optional reference banner at top, and a "Go deeper" expander for the lore-rich persona.

  • Pre-filled from "The Grumpy Sage" — name suggested, description seeded, three chips on, palette implied. User can blow it all away or just tweak the name and continue.
  • Reference banner up top reminds the user their image is attached. Shown here as a compact one-line banner — replace/swap is one click.
  • Description is now multi-paragraph with a tall default. Power users can dump prose; casual users write one sentence.
  • "+ free text" chip opens an inline text field for personality words not in the predefined set. Vibe doesn't have to fit our taxonomy.
  • "Go deeper" expander reveals four optional fields: backstory, speech style, behavioral quirks, visual notes. Closed by default for casual users; lore-rich users live in here.
Progressive disclosure, not modal branching. One form, defaults that work for the casual user, depth available when needed. Nobody has to self-classify as "casual" or "power" up front.

02

The prototype gate.

Single biggest change in v0.2. Generate one base sprite, gate on it, iterate cheap. Failing here costs one imagegen. Failing after committing to the full pipeline costs eight.

  • Big preview · no other distractions. The whole screen is about evaluating one thing.
  • History strip below the preview. Image gen is non-deterministic; try 2 might've been the best one. Click any thumbnail to revert and re-anchor on it. We already have these PNGs on disk — wasting them is silly.
  • Always-visible feedback field, not a separate "adjust" mode. Type something + "Try again" → feedback-driven regen. Leave it blank + "Try again" → plain reroll for Codex randomness. Two actions, not three.
  • "+ helper chips" below the textarea — quick-insert phrases for common tweaks. Reduces typing friction for the casual user without forcing structure.
  • "See revised prompt" expander — open by default to demonstrate, but normally collapsed. Shows the rewritten prompt + Codex's one-line summary of what changed. Inspectable. Editable directly for power users.
  • Soft fatigue nudge after iteration 4: "the brief might need a tweak →" linking back to Step 2. Local feedback loops have diminishing returns; the escape hatch is to fix the root cause.
Why this is two model calls per "Try again": a text-only rewrite turn (cheap, ~tenths of a cent) followed by an imagegen turn (expensive, ~$0.04). Splitting them lets us inspect/retry the rewrite without burning an imagegen, and surfaces the revised prompt for trust.

04

Pipeline, post-prototype.

Same screen as v0.1's Screen 04, with one structural change: the base row is already done when this screen loads — accepted from the prototype gate. Pipeline has 7 rows to generate, not 8.

  • Base shows "canonical identity ✓" instead of "candidate accepted." It's not just done — it's the anchor.
  • "14 total imagegen calls" reflects the iterations from the prototype gate (4 prototypes + 1 each for rows 02 and the in-progress 03 + ~8 prompt rewrites). Honest cost surfacing.
  • Per-row Replace still works. Re-running a row costs one imagegen; downstream rows are still grounded on the unchanged base.
The architectural payoff of the prototype gate: by the time we get here, the user has already approved the visual direction. The remaining 7 generations are grounded on it, so identity stays consistent. No mid-pipeline "wait, this doesn't look like Wendell" surprises.
